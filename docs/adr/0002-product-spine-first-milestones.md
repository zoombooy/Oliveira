# ADR 0002: 里程碑按产品脊柱排序，治理设施分期生长

日期：2026-09-24
状态：已接受

## 背景

完整的工程治理设计（Run 状态机、审批、沙箱、Skills、外部副作用）
如果在地基阶段全部预建，单人项目将在见到任何产品价值前
消耗数周，且未经过真实 Agent 行为检验的状态机大概率返工。

## 决策

里程碑顺序为：可用的 RAG → 事实模型+评估 → Agent 循环（此时才固化状态机）
→ 记忆/审核/审计 → 沙箱与扩展。
治理组件推迟到其服务的真实行为存在之后实现；
宪法性原则（事实源/投影分离、证据先行、模型不执行不可逆动作）
从第一天起生效，但实现形态随里程碑简化（如 M0′ 的 Run 只是一行 status 字符串）。

## 后果

- 每个里程碑结束都有可演示的产品价值；返工面限于推迟的治理组件。
- 中间态（如 status 字符串）必须在架构文档中显式登记为"临时形态"，
  防止临时实现被误认为最终设计。
