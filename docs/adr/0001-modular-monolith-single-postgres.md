# ADR 0001: 模块化单体 + 单 PostgreSQL

日期：2026-09-24
状态：已接受

## 背景

Oliveira 由个人开发者主导，需要控制部署与维护成本，
同时承载向量检索、全文检索、知识图谱、任务队列等能力。

## 决策

1. 采用 FastAPI 模块化单体；模块以 package + service 层为边界，
   不预建微服务隔离仪式（接口层/跨模块禁访问等在出现真实团队协作前不强制）。
2. 只使用一个 PostgreSQL（pgvector + FTS + 边表 + 队列表），
   不引入 Milvus / Neo4j / Redis / 独立检索服务。
3. 索引与图投影定位为可重建产物（见架构文档 §3.1）。

## 后果

- 一台 4C8G 机器可跑全栈；备份/迁移只有一套数据。
- 单库承载多职责的性能天花板出现时，由真实压测证据驱动再拆
  （候选顺序：检索投影 → 队列 → 图投影）。
